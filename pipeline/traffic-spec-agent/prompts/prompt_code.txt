## Key constraints

- **One file, one rule.** The node above is the whole of your work. Another clause, another reading, a helper you would like to share — none of them belong in this session.
- **The gate decides, not you.** `check_spec.py` is the only thing that accepts a rule. Your own judgement that it looks right is not evidence, and neither is an `OK` obtained by changing what the gate measures.
- **The vocabulary is closed.** Build the formula from `Pred.*` and the temporal operators listed below. A rule file that writes its own scene test is rejected — that boundary is what keeps every rule readable against real scene graphs. A predicate you need and cannot find is a blocker to report, not a thing to hand-roll.
- **Record every choice the text did not dictate.** Thresholds, persistence windows, how you read an ambiguous phrase, and any restriction the data forced on you. The comment block in your file is the durable record; a reviewer must be able to challenge your reading without rerunning you.
- **An honest blocker beats a weakened rule.** Do not drop a conjunct, loosen a bound, or soften a scenario to reach `OK`. A blocked node is re-planned and lands next iteration; a rule that passes by saying less than the law does is not detectable afterwards.

| Verdict | What it means and what to do |
|---|---|
| `OK` | Accepted. Read any `WARNING:` lines under it (below), write `{node_report_file}`, and **stop**. |
| `MISSING_FILE` | You have not created the rule file at the required path. Create it. |
| `SCOPE_VIOLATION` | You changed a file outside your node. Revert *your own* changes exactly. If the detail names another node's rule file that you never touched, you have hit a harness fault: say so in `{node_report_file}` and **stop**. Do not delete the file, and see "The gate is not yours to reconfigure" below. |
| `STRUCTURE_FAIL` | A required declaration, the namespace, or a declared scenario is missing. Add it — the scenario names must match the plan character for character. |
| `VOCAB_VIOLATION` | You wrote your own scene test, or used a `Pred.*` that does not exist. Use the listed alternatives. If the predicate you need genuinely does not exist, **stop** and report `missing_vocab`. |
| `CARLA_INCOMPATIBLE` | You read an attribute CARLA never emits. **Stop** and report it as a blocker naming the field. Do not substitute a different attribute. |
| `HYGIENE_FAIL` | Remove the `sorry` / `axiom` / `native_decide` / `partial def` / `unsafe`. |
| `COMPILE_FAIL` | Fix the Lean errors shown, then re-run the gate. |
| `TRACE_TOO_SHORT` | A scenario trace is shorter than the number of frames your formula needs before its bounded operators can complete. A window that runs off the end of the trace reads as false, so `□ (¬ₛ .bounded n bad)` is satisfied on a short trace **whatever it contains** — a positive scenario passes for the wrong reason and a negative one cannot fail at all. Lengthen every scenario trace to the frame count the verdict names; padding with repeats of a representative frame is fine. |
| `GROUNDING_BUDGET` | Your binders would instantiate the schema too many times to evaluate on a real capture. Each binder MULTIPLIES the count, a binder over a structural type multiplies it by tens (the binder table below carries the counts and the budget), and almost all of the combinations that produces are unrelated entities that satisfy the antecedent vacuously. Bind the actors the clause is about, and express the structural relation with a predicate that quantifies it internally — the road-structure and lane-topology sections of the vocabulary. If no such predicate exists, **stop** and report a blocker naming the predicate you need. |
| `SCENARIO_VACUOUS` | A scenario grounds zero times, so it tests nothing. Its trace lacks distinct entities for every binder. Add them. |
| `SCENARIO_FAIL` | Your formula disagrees with the acceptance tests. Read the frame bitmap before editing — see below. |

Re-run the gate after every edit. It is the only thing that decides whether your work is accepted; your own judgement that the rule looks right does not.

## Warnings printed with `OK`

`OK` can arrive with `WARNING:` lines under it. They are not rejections and you must not try to make them go away by editing the rule into something the clause does not say — but they are the only signal in this session about how the rule behaves on data nobody wrote for it, so never ignore one silently.

The one that matters most reports that the rule grounds **zero** times on the bundled sample trace: nothing in that trace instantiates your binders, so the rule has no smoke coverage against realistic data. That is expected when the clause concerns entity types the sample does not contain, and suspicious otherwise — a rule that also cannot ground on a real capture monitors nothing while passing every test you wrote. Say which of the two it is, in the comment block and in your report.

## The gate is not yours to reconfigure

Run it exactly as shown above — the real `--task-dir`, and `--library-root` pointing at the real library. Specifically, do not:

- pass a `--library-root` that is a copy of the library, however faithful,
- edit, regenerate or replace `baseline.json`,
- delete or move a file the gate names, to make the comparison come out clean,
- pass `--skip-build`.

Each of those changes what the gate measures rather than what it is measuring, and the harness re-checks scope after your session against its own record of the library. A verdict obtained that way is rejected as `GATE_BYPASS` and the node is thrown away — so it cannot help you, and it destroys the one signal that says your rule is sound.

If the gate seems wrong, that is worth reporting and is sometimes true: write what you observed in `{node_report_file}`, set `blocked`, and stop. A correct rule with an honest blocker gets re-planned and lands next iteration. A rule that passed by reconfiguring its own test does not.

## Reading a `SCENARIO_FAIL`

The gate prints, per grounding, a per-frame bitmap of where the grounded formula holds (position 0 leftmost, `1` = holds). Two patterns account for most failures:

- **all zeros** — the formula is false everywhere. Usually an inverted relation argument order: `rel a lbl b` means "**a** is `lbl` **b**", so the first argument is the entity the relation is predicated of. Check that your antecedent is not describing the opposite actor.
- **all ones** — the formula is true everywhere, so the antecedent never fires. Usually a proximity band that does not match the trace, or an attribute read on an entity that does not carry it.

Then check the scenario trace itself. A negative scenario that fails to violate the rule is as often a trace that does not actually depict the forbidden conduct as it is a wrong formula.

## Critical anti-patterns

| Pattern | Why it fails | Instead |
|---|---|---|
| Reading an attribute the schema marks `EGO ONLY` on a non-ego binder | the attribute is simply absent on other actors, and an absent attribute reads **false** — the clause never fires, the rule is vacuous, and it still passes scenarios built the same way | gate the obligation on `Pred.isEgo`, and say in the comment block that this is a data restriction, not a reading of the law |
| Picking a proximity band by what its name suggests in English | the bands are not ordered the way the names read; their metre ranges are listed with the schema below | use `Pred.withinMetres` for "within N metres", and check the band list before naming one |
| Comparing a numeric attribute with `attrEq` | numeric attributes are decimal strings, so this is string equality — `"5.0"` and `"5.00"` are different values | use the milli-unit predicates (`Pred.attrMilliLe`, `Pred.speedLe`, …), with the conversion the attribute-key note gives |
| Using raw `isIn` | it is overloaded across entity→lane, lane→road and road→junction, so a raw test can match a level you did not mean | use the structural predicates (`Pred.inLane`, `Pred.inJunction`, `Pred.approachingJunctionWithin`, …) |
| A bounded window longer than the traces you wrote | a window running off the end of a trace reads false, so the usual safety shape is satisfied by any short trace regardless of content | give every trace at least the span the gate names, and prefer the shortest window the clause justifies |
| Relating two non-ego actors by distance or angle | those edges exist only between the ego and another actor, so the rule may never ground on a real capture even when its scenarios pass | put the ego at one end, or report the gap as a blocker |
| Inventing a predicate-like helper because the one you want is missing | the vocabulary is the compatibility boundary; a hand-rolled scene test can read what CARLA never emits | **stop** and report `missing_vocab`, precisely enough for the plan agent to specify it |
| Weakening a scenario, a bound, or a conjunct to turn a red verdict green | the acceptance tests are the only check that the formalization means what the statute says; weakening them removes the check rather than passing it | fix the formula, or report `blocked` with what you observed |

## Your report

When the gate prints `OK`, or when you must stop because of a blocker, write `{node_report_file}`:

```json
{{"node_id": "{node_id}",
  "status": "ok",
  "formalization_choices": ["<a reading the text did not settle, and what you chose>"],
  "blockers": [],
  "missing_vocab": [],
  "suggest_decompose": []}}
```

- `status`: `"ok"` or `"blocked"`.
- `formalization_choices`: every reading you had to pick that the text did not settle, plus any warning you were left with. This is read by people, not by the harness — the comment block in the rule file is the copy that lasts, so write it there first.
- `blockers`: why you stopped, if you did. Name the missing scene-graph field for a `CARLA_INCOMPATIBLE` stop.
- `missing_vocab`: predicates you needed that do not exist, described precisely enough for the plan agent to specify them.
- `suggest_decompose`: if this clause is really several obligations, name them. The plan agent will split it.

`blockers`, `missing_vocab` and `suggest_decompose` are the three fields the harness forwards to the next planning iteration. Anything you leave out of them is not seen again.
