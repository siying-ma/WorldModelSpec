# Project Report

This project is a small Lean 4 prototype for expressing and checking safety-related rules over driving scenes. It is inspired by the paper Scene Flow Specifications: Encoding and Monitoring Rich Temporal Safety Properties of Autonomous Systems and related SceneFlowLang / SGSM work, but re-expresses the property language and monitoring semantics in Lean 4. In simple terms, it treats a driving episode as a sequence of scene snapshots, lets the user write rules about what should or should not happen over time, and then checks whether a recorded trace satisfies those rules. The repository was built as a quick exploration of what Lean 4 can do for this kind of specification and monitoring task.

I worked with LLMs to implement a basic pipeline. On the Lean side, I implemented temporal operators including next, until, release, eventually, always, and a bounded operator, alongside the usual Boolean connectives and atomic predicates. I also defined core scene objects such as entities, relations, and traces, built a small temporal-logic language for describing properties of those traces, and implemented an executable monitor that returns whether a property is satisfied or violated. The project includes several example properties, such as yielding at intersections, maintaining safe following distance, and checking whether an opposing lane is clear, along with sample traces that demonstrate both correct and violating behavior.

The current state is that the Lean specification and semantics are implemented, along with some example properties and theorems. The data adapter is also implemented in Python, which converts RSV graph frames and ego logs into a format that can be checked by the Lean monitor. The RSV graphs come from [CARLA scene-graph tooling](https://github.com/less-lab-uva/carla_scene_graphs).
